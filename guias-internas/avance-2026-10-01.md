## Cambios realizados

### 1. Experiencia del negocio: de 15 a 20 años

### 2. Favicon en la pestaña del navegador

La pestaña mostraba un ícono genérico porque no había favicon declarado. Se generó a partir
de `img/LOGOshadow.png` (que pesaba 294 KB y medía 1501×1501 px, demasiado grande para un favicon):

- `public/img/favicon-64.png` — ícono de la pestaña
- `public/img/favicon-512.png` — ícono grande para PWA
- `public/img/favicon-180.png` — `apple-touch-icon` para iOS

Y se agregaron las etiquetas correspondientes en el `<head>` de `public/index.html`.

### 3. Ícono oficial de WhatsApp

El ícono de WhatsApp era un globo de diálogo genérico con trazos, no el logo real.
Se reemplazó por el logo oficial (el mismo que está en `public/img/Iconos/whatsapp.svg`),
con `fill="currentColor"` para que herede el color del header y se ponga blanco al hacer
hover, igual que los demás íconos.

**Nota de consistencia:** el ícono nuevo es relleno sólido mientras que Facebook, Instagram y
Linktree son de trazo. Si se quiere que todos se vean iguales, hay que convertir los otros
tres a relleno.

### 4. Saltos de línea LF (`.gitattributes`)

Git mostraba el aviso "LF will be replaced by CRLF" en cada `git add`. No era un error,
solo un aviso de conversión de finales de línea en Windows. Se creó `.gitattributes` con:

```
* text=auto eol=lf
```

para que los archivos de texto se guarden siempre con LF y el aviso desaparezca.

### 5. Regla de push y vista previa local

Se actualizó `AGENTS.md` para dejar por escrito:

- **No hacer `git push` sin orden explícita del usuario.** Cada push nuevo necesita una
  instrucción nueva, aunque ya se haya autorizado antes.
- Cómo levantar el sitio en local antes de subir los cambios:
  ```
  python -m http.server 8000
  ```
  desde la carpeta `public/` y abrir `http://localhost:8000`.

## Problema detectado: el sitio en vivo sirve una versión vieja

Al revisar `https://sanitarios-la-pampa.josuecavargas.workers.dev` se encontró que:

- Sigue mostrando "15 años" y el ícono viejo de WhatsApp
- `img/favicon-64.png` responde **404**
- La API de GitHub no registra **ningún deployment** para el repo

Conclusión: el Worker se desplegó una sola vez (después del commit de la migración, porque el
CSS sí carga) pero **no está conectado al repositorio para redesplegar**. Los pushes de hoy
nunca llegaron al sitio.

### Solución

En el dashboard de Cloudflare (Workers & Pages → proyecto → **Builds**):

1. Conectar el repositorio `josuecavargas-star/sanitarios-la-pampa`
2. Rama: `main`
3. Build command: vacío
4. Deploy command: `npx wrangler deploy`
5. Root directory: `/`
6. Revisar la pestaña **Builds** por si hay builds fallidos
