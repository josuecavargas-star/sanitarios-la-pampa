## Propósito

Sitio web estático en español para Sanitarios La Pampa, dedicado a la limpieza de tanques sépticos y al destaqueo de tuberías en Guanacaste, Costa Rica. El sitio presenta los servicios, una galería de trabajos, información de la empresa y datos de contacto.

## Tecnología y forma de ejecución

- HTML5, CSS3 y JavaScript vanilla.
- No usa framework, gestor de paquetes ni proceso de compilación.
- No existen `package.json`, scripts de npm, linter ni typecheck.
- Para previsualizarlo localmente:

```powershell
cd "C:\Users\josue\Desktop\netlify\sanitarios-la-pampa"
python -m http.server 8765
```

Abrir `http://127.0.0.1:8765` en el navegador.

## Estado actual de la interfaz

### Encabezado

- Encabezado sticky con logo y navegación.
- En escritorio los enlaces aparecen en una fila.
- En pantallas pequeñas aparece un botón de menú hamburguesa.
- El menú móvil se abre y se cierra desde `js/main.js`.

### Héroe

- Texto principal sobre limpieza de tanques sépticos y destaqueo.
- Botones “Llamar ahora” y “Ver servicios”.
- Composición visual con un círculo central que contiene `img/LOGOshadow.png`.
- Tres tarjetas flotantes separadas para:
  - Destaqueo.
  - Tanques sépticos.
  - Servicio 24/7.
- Las tarjetas tienen animación suave e independiente.
- En pantallas pequeñas la composición se apila verticalmente para evitar superposiciones.

Referencias principales: `index.html:33-76`, `css/styles.css:146-308`, `css/styles.css:699-791`.

### Galería

- Slider de tres diapositivas con flechas, puntos indicadores, autoplay, swipe táctil y teclado.
- Las diapositivas usan las fotos:
  - `_MG_8392.jpg`
  - `_MG_8409.jpg`
  - `_MG_8412.jpg`
- Las imágenes se cargan como fondos CSS con un degradado oscuro encima para mantener legible el texto.

Referencias principales: `index.html:78-121`, `css/styles.css:560-697`, `js/main.js:54-121`.

### Servicios y nosotros

- Dos tarjetas de servicios con íconos SVG.

  - Más de 15 años de experiencia.
  - Servicio 24/7.
  - Tres líneas de contacto.
- Las tarjetas y estadísticas tienen animación de aparición al hacer scroll cuando el navegador soporta `IntersectionObserver`.

Referencias principales: `index.html:123-181`, `css/styles.css:310-443`, `js/main.js:123-146`.

### Contacto

- Información de horario, cobertura y tres teléfonos enlazados con `tel:`.
- Formulario con nombre, teléfono y mensaje.
- El formulario muestra una confirmación visual después de enviar, pero **todavía no envía los datos a ningún servidor**.
- El año del footer se actualiza automáticamente.

Referencias principales: `index.html:184-247`, `css/styles.css:445-558`, `js/main.js:29-52`.

## Decisiones de diseño

- Paleta principal verde (`#189b1b`) sobre blanco, con tonos claros y oscuros derivados.
- Diseño limpio, moderno y orientado a conversión telefónica.
- Se mantienen los SVG inline para los íconos y no se agregaron dependencias externas.
- Se priorizó una implementación estática compatible con Netlify.
- El logo central del héroe reemplazó al ícono genérico anterior para que la composición sea más reconocible.

## Responsive

El diseño incluye tres rangos principales:

- Hasta 1150 px: el héroe pasa a una sola columna.
- Hasta 900 px: las secciones “Nosotros” y “Contacto” se apilan y aparece el menú móvil.
- Hasta 520 px: se reducen paddings, la galería y las tarjetas del héroe se adaptan al ancho disponible.

## Limitaciones y próximos pasos recomendados

1. Conectar el formulario a Netlify Forms, Formspree u otro servicio real; actualmente solo simula el envío.
2. Revisar y optimizar el peso de las fotografías antes de producción.
3. Añadir una política de privacidad si el formulario comienza a recopilar datos.
4. Mejorar accesibilidad del menú con `aria-expanded` y estados de foco.
5. Considerar `prefers-reduced-motion` para respetar a usuarios que desactivan animaciones.
6. No hay una configuración específica de Netlify ni `netlify.toml`; el sitio puede desplegarse como archivos estáticos desde la raíz.

## Instrucciones para otra IA

1. Leer esta guía y después inspeccionar `index.html`, `css/styles.css` y `js/main.js` antes de modificar.
2. Mantener el estilo visual y la estructura actual salvo que el cambio solicitado requiera otra cosa.
3. Probar la vista local con el servidor estático indicado.
4. Revisar el resultado en escritorio y móvil.
5. No reescribir el commit inicial ni hacer `push --force` sin autorización explícita.
6. Usar mensajes de commit claros en español para cambios posteriores.
